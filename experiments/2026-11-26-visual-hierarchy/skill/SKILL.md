# 视觉层级（Visual Hierarchy）

一句话咒语「优化 UI 视觉层级」之所以偶尔有效，是因为它在模型里索引到了一整套设计共识；它不稳定的原因也在这里——索引不等于执行，更不等于验收。这个 skill 把那句咒语展开成可执行的三层：**先定主次表，再做眯眼验收，最后按顺序改**。判定权在验收协议，不在感觉。

## 分工边界（不许越界打架）

| 谁 | 管什么 | 不管什么 |
|---|---|---|
| **visual-hierarchy（本 skill）** | 主次结构：谁是第一落点、分组、显著度分配、主行动唯一性；以及层级验收（眯眼测试） | 具体数值工艺 |
| huashu-design | 设计流程：三方向初稿、选定执行、打磨环、导出 | —— 它的打磨环在收尾阶段调用本 skill 做层级验收门（见下） |
| better-typography | 字号阶梯、行高、字重、字体搭配的数值 | 哪个元素该大该小（那是本 skill 的主次表先定的） |
| better-layout | 分组间距比、对齐、响应式结构的数值 | 分组的内容归属（本 skill 定） |
| better-ui / better-colors | 圆角、阴影、描边、色板与对比度测量 | 哪个元素配得上高对比（本 skill 定） |

冲突时的裁决顺序：主次表（本 skill）→ 结构（better-layout）→ 数值（typography/colors/ui）。工艺 skill 的数值不得反过来推翻主次表；主次表也不得指定具体像素，像素归工艺 skill。

## 第 0 步 · 入口分流 + 主次表（动手改之前先写，5 分钟）

先分流，三种入口不共用一套动作：
- **改既有页面**：全套流程（主次表 → 眯眼验收 → 按顺序改 → 复测）。
- **从零生成**：只做主次表 + 结构草案，生成后回到眯眼验收；不许拿咒语当生成指令甩一句了事。
- **单个组件**：只核对组件内部的主次与它在页面里的显著度等级，不重排全页。

然后写主次表。

任何一页先写一张三行表，写不出来说明页面本身没想清楚，改样式没用：

1. **第一落点**：用户 0.5 秒内必须看到的那一个元素，它同时回答「这页是干嘛的」或「现在要我干嘛」——只能有一个。
2. **唯一主行动**：全页只能有一个最高显著度的可点元素。其余行动一律降级（文字链、灰按钮、收进菜单）。
3. **可糊掉层**：眯眼后应该几乎消失的东西——次要标签、元数据、装饰、已完成/未解锁状态。它们存在是为了被读第二眼，不是第一眼。

页面复杂时把主次表展开成四级权重表，并先声明页面意图（浏览消费型 / 工具决策型，防套错模板）：Tier 1 核心钩子 1–2 项（视觉预算约 40%）、Tier 2 核心支撑 2–4 项（约 30%）、Tier 3 辅助与元数据（约 20%）、Tier 4 法律与低频入口（约 10%，剥离装饰）。配额是锁：Tier 1 超员，先降级再谈样式。

**反模式熔断（改之前先扫一遍，命中即先处理）**：卡片嵌套 >2 层；同一视口 ≥2 个实心主按钮；品牌强调色面积 >视口约 10%（语义状态色除外）；标签（Key）的字重/明度高于数值（Value）；>6 个同等大小同等样式的卡片平铺且无突出项。

## 第 1 步 · 眯眼测试（验收协议）

```bash
python3 <skill>/scripts/squint.py <截图.png> [--out DIR] [--radius N]
```

产出：`*_blur.png`（半径 = 图宽 2%）、`*_blur_gray.png`（去色）、`*_thumb.png`（64px 宽）、`*_metrics.json`。

模糊分两档用：轻档（半径 ≈ 图宽 0.8%，加 `--radius` 指定）看分组是否成立，重档（默认 2%）看最强的一两个焦点是否还在——单档会漏掉「表面清晰、实则平坦」的页面。计量以重档为准。

**两条硬规则（不许被任何总分或计量过线抵消）**：① 模糊后认不出这页是干嘛的 → 直接不通过；② 模糊后认不出主操作在哪 → 直接不通过。先过这两条，再看其余指标。注意眯眼测试只检验低空间频率下的宏观组织，它能被刷（巨型鲜艳按钮刷高分却可能破坏品牌与可读性）——所以它从不是总裁判，盲评与业务语义判断在它之上。

**计量读法**（脚本在 160px 缩略的模糊灰度图上，以亮度偏离均值 ≥30 的连通域为显著区域）：
- `competing_foci ≥ 3` → FAIL：多个大块在抢第一落点。
- 显著焦点只落在底部三分之一（`focus_rows == [2]`）→ WEAK-cta-only：按钮很响、主题没声，先补主题锚点再谈按钮。
- `competing_foci ≤ 2` 且焦点含上部 → 结构层 PASS（仍须过人工表）。

**人工对照表**（对着三张产出图逐条答是/否，任一「否」即不通过）：
1. 只看模糊图：能说出这页是干嘛的吗？（主题锚点——大图、大标题或标志性形状——在模糊后还认得出吗？）
2. 只看模糊图：第一眼落点是不是主次表里的第一落点？
3. 只看灰度模糊图：去掉颜色后主次还在吗？（只靠颜色撑的层级是假层级。）
4. 主按钮有且只有一个显著色块吗？它和第一落点是同一个区域，或紧挨着吗？
5. 次要信息在模糊后是否退成均匀的浅灰背景，而不是一堆小亮点？
6. 缩略图（64px）里还能分出「头 / 身 / 尾」的分组结构吗？

**盲评关卡（最硬的一条，计量过线也不能替代）**：把模糊图交给一个没看过原页面的评审者（人，或与改页面不同的模型/会话），只问两句：「这页是干嘛的？主操作是什么？」两句都答对才算过。评审者若就是改页面的模型，它知道答案，会脑补通过——必须隔离。计量指标可以被刷（加个大色块就能过焦点数），盲评刷不了。

复测回环上限 2 轮：第 3 轮还不过，停下来报主人——大概率是主次表（信息主次）没定，不是样式问题。

## 第 2 步 · 按顺序改（只按这个顺序，不许跳步）

1. **删**：先删重复主行动、抢眼的装饰、无主的横幅——显著度是零和的，删一个等于给主角加权。
2. **并**：把第一落点和主行动并进同一个容器（英雄卡/头部区），让「看懂」和「动手」发生在同一眼里。
3. **降**：次要元素成组降级——缩小、变灰、去掉底色与描边；已完成/未解锁状态只用深浅区分，不用饱和色。
4. **升**：最后才升主角——放大语义锚点（图/大标题）、加深容器、主按钮给全页唯一的饱和色。
5. **分**：组间留白 ≥ 组内间距 2 倍（数值细节转 better-layout），让分组在模糊后仍成块。

每改完一轮，回到第 1 步复测，blur 图与 metrics 一起存档，前后对照交付。

**决策记录（每轮修改必留，六字段）**：问题（最严重的一条）/ 证据（模糊图或原图的哪个区域）/ 判断（为什么它是问题）/ 决策（按什么顺序改）/ 代价（可能破坏什么）/ 验证（复测结果）。没有决策记录的修改视为没改完——它让修改可追问、可复核、可沉淀进反例库。

## 数值锚点（只是锚点，精确值归工艺 skill）

- 字号比：第一落点标题与正文 ≥ 2 倍；层级不超过 3 级显著度（主角 / 配角 / 背景）。
- 对比：主行动与其周围元素的亮度差要大到在灰度模糊图里仍是一个独立色块。
- 显著度预算：一屏饱和色（高彩度填充）面积 ≤ 约 15%，且只给主角与主行动。
- 留白：主角容器上下留白 ≥ 相邻组间距的 2 倍。

## 与 huashu-design 的配合点

huashu-design 的打磨环（polish loop）收尾时加一道**层级验收门**：每屏截图先跑 squint.py + 人工对照表，任一屏 FAIL/WEAK 就回到打磨环继续改，不进入交付；验收的 blur 图与 metrics 路径记进该项目的 polish-log.md。方向稿阶段（三方向）不跑本门——那时比的是方向，不是层级。

## 失效声明（每次交付必带）

诊断报告末尾必须用一两句写明：本页的问题里哪些不是视觉层级能解决的（信息架构、产品取舍、质感工艺），分别该由谁解决。不许用样式修改掩盖结构问题。

## 失效边界（这句咒语/这个 skill 救不了的）

- 信息架构本身错位：该拆页的挤在一页、该合并的散在多页——层级只能排已有信息的序，不能替你决定哪些信息该存在。
- 内容无主次：所有信息同等重要（或同等不重要）时，强行拉层级只会骗用户。
- 品牌/风格问题：层级对了页面仍可能「廉价」——本 skill 只管**感知秩序**（先看什么、后看什么），不管**视觉品质**（是否值得看、有无辨识度与质感）。发现品质问题时在失效声明里点名并转交（字体/色彩/质感归 better-* 与 huashu-design 的方向阶段），不要在本 skill 里加戏，更不许宣布「层级过了，所以设计好了」。
- 数据型 dense 界面（表格、仪表盘）：眯眼测试的前提是「扫读」，专业用户逐字读的界面只用第 0 步主次表，不用模糊判定。
