# 会诊收敛结论（小培培收口，非拼贴）

同场四家：GPT（云浏览器，带审美记忆触发）、Gemini（云浏览器 Pro；Camoufox 路登录态掉线后改派）、Claude（Camoufox+住宅出口 Free 号）、Grok（简报送达后撞 usage limit，缺席，不顶替）。各家原文存 consult/。

## 一句话咒语的机制——共识
四家（缺 Grok）一致：这句话不执行任何视觉测量，它是一个**高压缩的语义指针/路由锚点**。它在训练语料里与一整套设计共识强共现（字号对比、分组、留白、明度、CTA 突出、格式塔），输入它等于把生成分布拽向「设计师评审」模式并展开一份隐式清单，进而产生跨属性联动（字号/颜色/卡片/间距/按钮同时动）。视频里它显得灵，还有两个被点名的水分：演示场景恰是它最舒服的输入（已有内容、结构已对、只是样式平坦的现成页面），且「点击率略高」无对照组（Claude、Gemini 分别从证据与幸存者偏差角度指出）。

## 失效边界——共识
信息无主次/IA 错位（只能把垃圾排整齐）、业务语义与通用共识倒挂（该先看风险提示时模型会按商业惯性突出收益数字）、从零生成（回到模板平均解）、高密度数据界面（强拉层级会误删/折叠核心数据）、硬约束封死手段（品牌/组件库）、无视觉反馈闭环（改代码的模型读的是 DOM 信号、没有眯眼能力）、以及 GPT 独有且最对主人痛点的一条：**层级对了仍可廉价**——感知秩序 ≠ 视觉品质。

## 分歧（如实记录，我的取舍）
1. 模糊强度：Claude 主张两档（σ≈宽 0.8% / 2%）；GPT 主张三档（390px 基准 σ=4/8/14）；Gemini 给移动 2.5%–3.5%、桌面 1.2%–1.8%。取舍：协议用两档（轻 0.8% 看分组、重 2% 看焦点），2% 已在自家样本上实测能同时满足「字糊掉、块还在」；档数之争不影响判定结构。
2. 判定形式：GPT 给 100 分加权评分（80 通过）；Claude 反对只靠量化（指标可刷），主张盲评一句话为强制关卡；Gemini 给四项 Pass/Fail 线。取舍：采用 Claude+Gemini 的二值判定 + 两条硬规则（GPT 的「用途不可识别/主操作不可辨认直接不通过」被吸收为硬规则），不采用总分制——分数会给「刷指标」留门，盲评关卡（换一个没看过原页的评审者答两问）作为最终门。
3. 结构野心：GPT 主张扩成 Visual Intelligence 三能力系统（Diagnosis/Direction/Verification）；Claude 主张只补前后两头（决策前置+闭环验证）、数值与流程不重造。取舍：本轮按 Claude 的克制版落地为 skill（主人要的是能用的工具，不是新体系）；GPT 的三能力作为远期方向记下，不在本轮扩建。Gemini 的四级权重配额表与五条反模式熔断被吸收进主次表与诊断标签。

## 最终结构（已落地 skill）
入口分流（改既有/从零/单组件）→ 主次表（复杂页展开 Tier 1–4 配额 + 页面意图声明）→ 眯眼验收（squint.py 程序化模糊 + 显著焦点计量 + 人工六条对照 + 盲评关卡 + 两条硬规则，回环 ≤2 轮）→ 按序改（删→并→降→升→分）+ 反模式熔断 + 决策记录六字段 → 失效声明。数值只留锚点，精确值引用 better-typography/layout/ui/colors；huashu-design 打磨环收尾调用本验收作层级验收门。
